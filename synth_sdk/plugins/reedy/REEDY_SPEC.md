# Reedy Synth Engine — Specification

## Problem Statement

The user wants a new synth engine called "reedy" that produces a reedy, breathy timbre by interpolating between a pure sine wave and a smoothed square wave, with a per-voice noise layer that fades during attack and a vibrato-like effect that modulates the interpolation amount instead of pitch.

## Solution

A new synth engine (`reedy`) that lives alongside the existing engines (brassophone, arc, supersaw, etc.) in `synth_sdk/plugins/reedy/`. It uses the same infrastructure as brassophone: a precomputed warp table generated by a Python script, Q15 fixed-point math, the stock envelope, and the standard plugin API.

## User Stories

1. As a user, I want a new engine called "reedy" in the synth engine list, so that I can access it alongside the existing custom engines.
2. As a user, I want the blue knob to control how "reedy" the sound is — from pure sine (blue down) to a smoothed square wave (blue up) — so that I can shape the core timbre.
3. As a user, I want the reedy interpolation to use a three-point warp that squishes phase toward three anchors (0%, 50%, 100%) instead of the brassophone's two-point (edge) warp, so that the waveform has peaks at all three points for a reedy character.
4. As a user, I want the green knob to control the white noise mix level after the attack, so that I can add breathy texture to the sound.
5. As a user, I want the noise to start at 100% at note onset and fade toward the green knob's target during the attack, so that each note has a consistent breathy attack character.
6. As a user, I want the noise to be breathy (bandpass-filtered around 3 kHz) rather than raw white noise, so that it sounds like air/exhale and doesn't clash with the reedy tone.
7. As a user, I want the white knob to control the depth of a vibrato-like effect that modulates the interpolation amount, so that I can add timbral movement to the sound.
8. As a user, I want the orange knob to control the speed of this interpolation modulation (0–30 Hz), so that I can range from subtle shimmer to aggressive warble.
9. As a user, I want the interpolation modulation to sweep the full 0–100% range at maximum depth, so that the vibrato effect can reach both pure sine and full reedy extremes.
10. As a user, I want the interpolation modulation to be centered on the blue knob value when possible, so that the modulation feels balanced around my chosen timbre.
11. As a user, I want the interpolation modulation center to shift toward the middle when the blue value is near an edge and the full range can't fit, so that the modulation never exceeds valid bounds.
12. As a user, I want the interpolation modulation to use a sine LFO waveform, so that the movement feels smooth and natural.
13. As a user, I want the interpolation modulation to start immediately (no fade-in), so that the effect is present from the very first sample of each note.
14. As a user, I want all knobs to default to zero, so that the engine starts in a clean, predictable state.
15. As a user, I want each polyphonic voice to have its own independent noise source, so that chords sound wider and less correlated.
16. As a user, I want the engine to use the stock envelope for the noise fade, so that the attack character is consistent with the OP-1's ADSR behavior.
17. As a developer, I want the engine code to be split into `reedy.c`, `reedy_warp.h`, and `gen_reedy_warp.py` (matching the brassophone pattern), so that the warp table is editable and the engine code stays clean.
18. As a developer, I want the engine to compile and test via `python3 harness/audio.py reedy` without requiring a firmware build, so that I can iterate quickly.
19. As a developer, I want the engine to fit within the 32-byte voice object limit, so that it works with the OP-1's voice allocation.
20. As a developer, I want the engine to use only integer math (no floats per sample), so that it runs in real-time on the OP-1's Blackfin DSP.

## Implementation Decisions

### Engine Architecture

- **Engine symbol**: `ENGINE_reedy`
- **Engine kind**: `synth` (monophonic voice engine)
- **Engine slot**: next available order number (assigned by maintainer)
- **All defaults**: `[0, 0, 0, 0]` (blue=0, green=0, white=0, red=0)

### Knob Mapping

| Knob | Parameter | Range | Default |
|------|-----------|-------|---------|
| Blue | Interpolation amount (sine → reedy) | 0 (pure sine) to 1 (full reedy) | 0 |
| Green | Noise mix level (after attack) | 0 (no noise) to 1 (full noise) | 0 |
| White | Interpolation modulation depth | 0 (no modulation) to 1 (full range) | 0 |
| Red (orange) | Interpolation modulation speed | 0 Hz to 30 Hz | 0 |

### Warp Table

- **Dimensions**: 64 × 64 (matching brassophone's 64 × 65 pattern, but 64 columns for 0–100% interpolation)
- **Three-point exponential squish**:
  - Input 0–25% → squishes toward anchor 0%
  - Input 25–75% → squishes toward anchor 50%
  - Input 75–100% → squishes toward anchor 100%
- **Warp function** (per third, using the same exponential as brassophone):
  ```
  ph_f_sym = (ph_f - anchor) / half_width    # map to [-1, 1]
  abs_value = |ph_f_sym|
  x' = (exp(timbre * abs_value) - 1) / (exp(timbre) - 1)
  ph_f_warped = anchor + sign(ph_f_sym) * x' * half_width
  ```
- **MAX_TIMBRE**: 30 (matching brassophone)
- **Generator**: `gen_reedy_warp.py` (Python script, same pattern as `gen_warp_table.py`)

### Noise System

- **Source**: xorshift32 PRNG (`rng ^= rng << 13; rng ^= rng >> 17; rng ^= rng << 5;`)
- **Per-voice**: each voice has its own independent RNG state
- **Character**: breathy via two-pole resonant bandpass filter
  - Center frequency: 3 kHz
  - Q: 1.5
- **Fade behavior**:
  - At note onset: 100% noise
  - During attack: fades toward `green_knob * noise_level` using stock `OP1_VOICE_ENV`
  - Green=0: stays at 100% noise (no fade)
  - Green=100%: fades fully to green's target

### Interpolation Modulation (Vibrato-like)

- **Waveform**: sine LFO (using `OP1_SINE_TABLE`)
- **Speed range**: 0 Hz (orange=0) to 30 Hz (orange=100%)
- **Speed mapping**: linear from 0 to 30 Hz
- **Depth range**: full 0–100% interpolation range at white=100%
- **Centering**:
  - If blue ± half_depth fits within [0, 1]: center on blue
  - If it would exceed bounds: shift center toward 0.5 so the range fits
- **Starts immediately**: no fade-in, active from the first sample

### Voice State Layout (32 bytes)

```
uint32_t ph;              /* oscillator phase (2^32 = one cycle) */
uint32_t vibrato_phase;   /* interpolation LFO phase (2^32 = one cycle) */
int32_t  lp;              /* one-pole low-pass state (output filter) */
int32_t  bp_a;            /* bandpass filter pole A state */
int32_t  bp_b;            /* bandpass filter pole B state */
uint32_t noise_rng;       /* xorshift32 RNG state */
int32_t  interp_amount;   /* current interpolation amount (Q15, smoothed) */
int32_t  interp_target;   /* blue knob target (Q15) */
int16_t  held;            /* 1 from note_on until note_off */
int16_t  noise_level;     /* current noise level (Q15, 0..32767) */
```

Total: 8 + 4 + 4 + 4 + 4 + 4 + 4 + 2 + 2 = 36 bytes... that's too much. Let me recalculate.

The voice object is 0x24 = 36 bytes, but word 0 is the firmware-owned vtable (4 bytes). So we have 32 bytes (bytes 4–0x23) for our state.

```
uint32_t ph;              /* 4 bytes: oscillator phase */
uint32_t vibrato_phase;   /* 4 bytes: interpolation LFO phase */
int32_t  lp;              /* 4 bytes: output low-pass state */
int32_t  bp_a;            /* 4 bytes: bandpass pole A */
int32_t  bp_b;            /* 4 bytes: bandpass pole B */
uint32_t noise_rng;       /* 4 bytes: xorshift32 state */
int32_t  interp_amount;   /* 4 bytes: current interpolation (Q15) */
int16_t  held;            /* 2 bytes: note held flag */
int16_t  noise_level;     /* 2 bytes: current noise level (Q15) */
```

Total: 4+4+4+4+4+4+4+2+2 = 32 bytes. Fits exactly.

### File Structure

```
synth_sdk/plugins/reedy/
  plugin.json              # engine metadata
  reedy.c                  # main engine code (note_on, render, note_off)
  reedy_warp.h             # precomputed 64×64 warp table

```

### Build & Test

- Build: `python3 make_plugin.py plugins/reedy`
- Test: `python3 harness/audio.py reedy`
- Preview (if screen added later): `python3 harness/render.py reedy out.png`

## Testing Decisions

### What Makes a Good Test

- **External behavior**: The test should verify that the engine produces the expected audio output for given knob settings, not that internal state matches a specific pattern.
- **Boundary conditions**: Test that interpolation values are clamped to [0, 1], that the noise fade works correctly, and that the vibrato centering logic handles edge cases.
- **Performance**: The engine should complete a 128-sample block within the OP-1's real-time budget (verified via the harness's resource monitor).

### Test Modules

1. **Warp table correctness**: Verify that the generated warp table produces the expected three-point squish at maximum timbre (identity at timbre=0, three peaks at timbre=max).
2. **Noise fade**: Verify that noise level transitions from 100% to the green target during the attack envelope.
3. **Interpolation modulation**: Verify that the sine LFO modulates the interpolation amount correctly, with proper centering and clamping.
4. **Voice state fit**: Compile-time assertion that the voice struct fits within 32 bytes (`typedef char reedy_voice_fits[sizeof(reedy_voice_t) <= OP1_VOICE_SIZE ? 1 : -1];`).

### Prior Art

- `harness/audio.py` builds and renders plugins to WAV for listening tests.
- `brassophone/warp_table.h` and `gen_warp_table.py` provide the pattern for the warp table.
- `brass.c` provides the pattern for the engine structure (phase warp, bilinear interpolation, vibrato LFO).
- `clarinet.c` provides the pattern for per-voice noise (xorshift32 + one-pole filter).
- `arc.c` provides the pattern for two-pole bandpass filtering.

## Out of Scope

- Custom screen/GUI display (uses stock iter graphics)
- Page-press preset storage (no `page2_defaults` in plugin.json)
- Polyphonic noise correlation control (each voice gets independent noise by default)
- MIDI implementation (handled by the op1r framework)
- Master position stereo rendering (mono synth engine)
- Plugin file distribution (handled by maintainer)

## Further Notes

### Design Rationale

1. **Three-point warp**: The brassophone's two-point warp (edges) creates a delta-like waveform. The three-point warp (0%, 50%, 100%) creates a waveform with peaks at all three points, producing a reedy/brassy character with both even and odd harmonics.

2. **Interpolation modulation instead of pitch modulation**: The white/orange knobs modulate the interpolation amount (timbre) rather than pitch. This creates a timbral vibrato effect — the sound's character wavers between sine and reedy — rather than a pitch vibrato. This is a distinctive sonic character that differentiates reedy from other engines.

3. **Breathy noise**: The bandpass-filtered noise adds an air/exhale quality that complements the reedy timbre. The 3 kHz center frequency emphasizes the mid-range where breath noise is most audible without clashing with the fundamental tone.

4. **All defaults zero**: Starting from pure sine with no noise and no modulation gives a clean, predictable baseline. Users can build up from there.

### Implementation Notes for the Developer

- The warp table generator (`gen_reedy_warp.py`) must handle the three anchor points correctly. Each third uses the same exponential function but offset to its anchor.
- The interpolation modulation centering logic must handle the edge case where blue ± half_depth would exceed [0, 1]. When this happens, shift the center toward 0.5.
- The bandpass filter must be implemented with two poles using Q15 fixed-point math. No per-sample division.
- The xorshift32 RNG must be initialized per-voice in `note_on`. A simple seed (e.g., voice index + phase) is sufficient.
- The noise fade uses the stock `OP1_VOICE_ENV` — read it once per block and ramp linearly across the block (same pattern as brassophone's envelope handling).
